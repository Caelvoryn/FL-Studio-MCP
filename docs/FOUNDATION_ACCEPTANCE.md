## New structured tools and safety

- `fl_foundation_state(checkpoint_path=None)` aggregates existing live bridge endpoints.
  An optional saved FLP is parsed read-only, explicitly labeled as a potentially stale checkpoint.
  There is no fabricated empty live Playlist/automation list.
- `fl_foundation_batch(edits, expected_title)` supports only tempo, channel volume/pan,
  Mixer volume/pan/name. It preflights the whole batch, checks live item bounds before calling
  native single-item readers, exact names and old values, and independently reads after writes.
  Maximum32 edits, finite normalized values, stopped transport/recording, no automatic replay.
  Mixer rename is separate from other edits on that same track to keep identity guards meaningful.
- `fl_foundation_pattern(action, name, expected_count, expected_title, source=None)` supports
  direct new/clone metadata operations. Clone source must exist. It returns actual selected
  index and warns of renumbering. `notes_verified=false` until separate native/content verification.
- `fl_foundation_route(...)` enables/disables existing Mixer sends, using the real routing graph.
  It rejects self/Master-source/nonexistent routes, feedback cycles and removal of all paths
  to Master. Exact names/old route are required. Source and destination states are not guessed.

Writes require an independently owned saved session from `fl_host_project_file`, plus the
existing candidate-only `FLSTUDIO_MCP_ENABLE_DIRECT_VST_WRITES=1`. No installed configuration
was changed. Default registry48, direct opt-in54, legacy compatibility93; exact registry
tests also verify that unrelated legacy writers remain hidden in direct mode.

Batch edits are sequential, not atomic. Failure returns completed/uncertain writes and requires
reobservation; no rollback onto a potentially changed target. Shared-name targets/project IDs
remain limited by the old protocol, so do not concurrently edit a test project during a batch.

## Concrete remaining bridge gaps

Actual runtime lists54 channel API functions,75 Mixer functions and the observed Playlist/
arrangement modules. It includes`setChannelName`,`setTargetFxTrack`,`midiNoteOn`,`setGridBit`,
`setRouteToLevel`,`automateEvent`; those functions are not all exposed by the installed bridge.
Real requests for currently absent command names returned`Unknown command`, without execution.
This distinguishes a missing bridge handler from a missing official host API.

The next prerequisite for those supported official functions is a separately selectable,
real-tested candidate controller/bootstrap that leaves the stable binding intact. A safe
no-image interpreter bootstrap was not established here. For full notes use official Piano Roll
Score scripts; for unsupported instantiation/Playlist/FX/curves use verified templates or
explicit auxiliary workflows. This report does not claim those alternatives are fully automated.
