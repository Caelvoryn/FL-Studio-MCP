# 实施前审计（2026-10-26）

读取 candidate 源码、全部工具函数、connection/daemon/Piano Roll生成器、第一阶段交付和第二阶段实物验收。新副本 system_candidate 从 a6a9a05 建立；原 candidate 与运行配置保持原样。

## 架构与启动

入口 fl-studio-mcp / python -m fl_studio_mcp.server，FastMCP stdio；TCPBridge→127.0.0.1:9787 daemon→MIDI SysEx→FL控制器，另一条生成 .pyscript+GUI快捷键写音符。脚本需先在目标Piano Roll运行一次。API写入返回不构成执行证据。现有 daemon 支持多客户端线程，单次socket锁不能保护完整多步骤任务。

## 历史与当前状态

第二阶段实物复核13/13通过；不代表新实现已通过。同机16.135秒原生Demo具有7音乐通道、单Pattern、3个Sytrus、4个Sampler、7路Mixer、Master自动化；A/B分别重开重导出PCM完全一致，用户确认B重复感改善。当前进程枚举未发现FL64；现场连接须重新实测。第一阶段24项离线回归正在重新执行。

## 缺陷、依赖和安全边界

1. Channel Rack筛选改变索引；channel_select不能保证已打开Piano Roll目标。未经身份回读不得写入。
2. 音符重写/量化仅保留四字段，release/color等丢失；生成脚本异常分支可能再次执行已部分完成的修改。
3. apply_notes将写文件和发送快捷键视为ok，compose外层也可能乐观报成功；需明确unverified。
4. safe_write需要审查是否校验期望值；跨过程并发没有整个事务锁。
5. TCP本机无认证，旧服务不能视为安全沙盒；不开放公网，不安装插件。
6. 目录发现已处理重定向Documents，不能因默认目录空判缺失。仅索引不证明授权可用。
7. GUI辅助仍为坐标方案，焦点/窗口/弹窗失败必须停下并报告；不虚构UIA支持。
8. pyproject1.0.0与__version__0.3.0不一致；FastMCP依赖宽泛，保留requirements-tested锁定快照。
9. MIT基底及上游版权保留；不把本机资源/控制器私有配置/日志/工程推到公开仓库。GitHub CLI当前未在PATH，需另查认证，不报告已发布。
